# Startup Sim 独立游戏化产品方向

Status: Godot product baseline
Owner: Codex
Date: 2026-05-18

## 1. 产品定位

Startup Sim 的目标是一款 AI 原生创业经营模拟独立游戏。

一句话定位：

> 玩家经营一家 AI SaaS 创业公司，通过办公室房间、角色反馈、自由 CEO 指令和确定性商业规则，在现金流、产品、客户、融资、团队和竞争压力之间做取舍。

核心原则：

> 真实商业作为底层逻辑，游戏性作为表层体验。

玩家看到的是办公室、行动、角色、事件、反馈和复盘；PMF、估值、现金流、融资成功率、客户留存和竞争压力由后台规则计算。

## 2. 当前技术路线

正式表现层：`godot/StartupSimGodot/`

规则核心：`csharp/StartupSim.Core/`

完整参考实现：`src/core/`

Godot 是后续唯一前端和主要表现层。Web/Vercel 路线已放弃，后续不再维护 React/Vite 前端。

## 3. 产品支柱

### 3.1 可操作办公室

办公室是主游戏棋盘，而不是背景图。

- 产品室：研发产品、修复质量、探索 PMF。
- 销售区：寻找客户、推进大客户、提升 MRR。
- 服务器区：支撑稳定性、AI 成本和交付能力。
- 会议室：董事会、融资、战略和重大事件。
- 招聘区：招募员工、调整团队结构、管理士气。
- 市场区：品牌、媒体、活动和客户线索。

### 3.2 行动卡代替财务考试

复杂商业机制必须包装成简单取舍：

- 研发冲刺：产品提升快，现金消耗高。
- 小步验证：产品提升慢，但减少闭门造车风险。
- 增长投放：用户上升快，但产品差时会放大流失。
- 招聘扩张：产能提升，但固定支出上升。
- 融资谈判：现金增加，但股权和董事会压力变化。
- 控制成本：延长现金流可支撑时间，但增长放慢。

行动卡默认只展示取舍，不展示公式；高级详情可以作为可选层。

### 3.3 AI 角色是玩法

AI 不只是聊天框，而是角色和反馈系统：

- CFO：现金流、预算、融资、破产预警。
- CTO：产品质量、技术债、研发路线。
- COO：交付、团队士气、组织压力。
- 投资人：估值、增长、风险偏好、谈判反馈。
- 客户：需求、抱怨、续费、流失原因。
- 竞品：价格战、产品升级、抢客户、融资消息。
- 媒体/市场：声誉、舆情、行业叙事。

AI 可解释、叙事、建议和解析自由命令；不能直接决定核心数值。

### 3.4 可复盘故事

每局都要能回答：

- 为什么成功或失败？
- 关键转折点是什么？
- 哪个角色提醒过玩家？
- 当时有什么可选补救？
- 下局可以怎么改？

失败不是惩罚弹窗，而是一次可复盘的创业故事。

## 4. 核心循环

单回合循环：

1. 观察办公室状态、核心矛盾和事件提示。
2. 点击房间或行动卡，选择本月经营动作。
3. 可选：输入自由 CEO 指令，系统解释会如何解析。
4. C# Core / TurnEngine 结算数值、事件、竞品、客户和董事会反馈。
5. 月度战报展示变化、原因、角色反馈和下一回合压力。

中期循环：

1. 建立产品基础。
2. 找到可验证客户需求。
3. 在现金流压力下选择增长、融资或收缩。
4. 扩张团队和销售体系。
5. 形成产品、市场、资本或大客户路线。

长期循环：

1. 形成公司风格：产品信仰、资本狂飙、大客户、精益创业、产业合作等。
2. 渐进解锁 PMF、回款、毛利、组织、合规、上市路径。
3. 进入结局：破产、被迫出售、A 轮成功、行业独角兽、IPO、技术孤岛、创始人出局等。

## 5. AI 边界

AI 可做：

- 自由命令解析。
- 角色反馈。
- 事件叙事。
- 复盘生成。
- 轻量角色记忆。

AI 不可做：

- 不直接修改现金、用户、估值、产品分等核心数值。
- 不绕过 StateGuard 和 TurnEngine。
- 不凭空生成投资方董事。
- 不把专业指标默认压给玩家。
- 不让自由文本变成无限制沙盒。

推荐数据流：

```text
Player Input
  -> Intent Parser / Command Preview
  -> ActionPlan
  -> StateGuard
  -> C# Core deterministic simulation
  -> Board / Customer / Competitor / Insight facts
  -> AI narrative layer
  -> Godot monthly report
```

## 6. 资产与美术管线

生成型视觉资源继续遵守：

- 使用 image-2。
- Prompt 存入 `design-assets/image-2/prompts/`。
- 可复用导出存入 `design-assets/image-2/exports/`。
- 资产登记进入 `design-assets/manifest.json`。
- Godot 引用稳定导出，不直接依赖生成过程。

优先级：

1. 办公室房间背景和热点区域。
2. 员工、董事会、客户、投资人头像。
3. 行动卡插画。
4. 事件、危机、成就图标。
5. 结局复盘插画。

重要 UI 文案不应烘焙进图片。

## 7. Godot 路线图

### G0：工程与规则桥接

目标：Godot 项目可启动、可编译、可调用 C# Core。

已完成：

- Godot 4.6.x .NET 工程骨架。
- 主场景和办公室热点脚本。
- `PreparedActionSnapshot` / `TurnResultSnapshot`。
- `GodotTurnBridge` 调用 `StartupSim.Core`。
- CI 中构建 Godot C# 项目。

### G1：本地可玩垂直切片

目标：不用 Web，Godot 中可以完成“选房间 -> 准备行动 -> 执行回合 -> 显示月报”。

验收：

- 至少 5 个房间热点。
- 每个房间至少 1 个行动入口。
- 行动提交后通过 C# Core 结算。
- HUD 显示现金、现金流可支撑时间、MRR、用户、产品、声誉、股权、估值。
- 月度战报显示变化、原因和下一步压力。

### G2：C# Core 规则扩展

目标：Godot 可以离线跑完 12 个月基础局。

验收：

- StateGuard 可拦截不可承受预算。
- 融资估值、拒绝和反报价同源。
- 董事会、竞品、客户、洞察输出事实快照。
- 结局和复盘事实可由 Godot 展示。

### G3：办公室模拟感

目标：办公室看起来像经营空间。

验收：

- 房间有状态：正常、风险、机会、改善、阻塞。
- 角色或气泡反馈来自 settled facts。
- 行动结果有轻量动画或状态变化。
- 信息密度低于旧 Web 仪表盘。

### G4：AI 原生体验

目标：自由 CEO 指令、角色反馈和复盘成为核心卖点。

验收：

- 命令预览只读，不推进回合。
- 角色记忆引用历史事实。
- AI 叙事只消费结算事实。
- AI 不可用时仍有 deterministic fallback。

### Beta：可分发桌面版

目标：Godot 导出 Windows 可试玩包。

验收：

- 本地存档。
- 离线 demo。
- 导出脚本。
- 资源体积和加载流程可控。
- 复盘、成就和至少 5 个结局可展示。

## 8. 当前不做

- 不再推进 Unity 主线。
- 不继续大规模打磨 React/PixiJS 作为最终外壳。
- 不做完整 3D 办公室。
- 不做多人联机。
- 不把上市、债务、回款、PMF 多指标一次性压给玩家。
- 不让 AI 直接生成或修改核心数值。

## 9. 下一步执行建议

下一步应做 `G1：Godot 本地可玩垂直切片`：

1. 给 Godot 补自动化脚本：检查、导入、构建。
2. 在主场景中把 `GodotTurnBridge` 实例化并接上控制器。
3. 做最小 HUD 和月度战报。
4. 给 5 个房间建立可点击行动。
5. 每个行动生成 `PreparedActionSnapshot`。
6. 提交行动后显示 `TurnResultSnapshot`。
7. 添加 Godot/C# 侧测试或脚本检查。
8. commit + push，并确认 CI 绿色。
