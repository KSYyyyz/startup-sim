# Startup Sim 独立游戏化产品方向

状态：Godot 产品基线
负责人：Codex
日期：2026-05-18

## 1. 产品定位

Startup Sim 的目标是一款创业公司主题的俯视角办公室建造经营独立游戏。

一句话定位：

> 玩家经营一家 SaaS 创业公司，以公司发展、收益增长、市场地位和成就解锁为主线；办公室区域、设施升级、员工培训成长和日常模拟是支撑公司经营的系统。

核心原则：

> 真实商业作为底层逻辑，游戏性作为表层体验。

玩家看到的是办公室空间、区域、设施、员工、角色、事件、反馈和复盘；PMF、估值、现金流、融资成功率、客户留存和竞争压力由后台规则计算。

## 2. 当前技术路线

正式表现层：`godot/StartupSimGodot/`

规则核心：`csharp/StartupSim.Core/`

完整参考实现：`src/core/`

Godot 是后续唯一前端和主要表现层。Web/Vercel 路线已放弃，后续不再维护 React/Vite 前端。

## 3. 产品支柱

### 3.0 公司经营主线

主线目标不是“把办公室摆满”，而是让公司变强并取得可见成果：

- 收入增长、现金流改善、客户增加、产品变强。
- 完成阶段目标，例如首批客户、月收入突破、融资成功、市场份额提升。
- 解锁成就，例如现金流逆转、明星团队、稳定交付、竞品反杀、A 轮成功。
- 形成不同经营风格，例如产品领先、销售驱动、稳健盈利、资本扩张、大客户路线。

办公室建造、设施升级、员工培训和员工日常需求都必须服务于这条经营主线。

### 3.1 可建造办公室

办公室是主游戏棋盘，而不是背景图或 CLI 行动入口。

- 玩家以俯视角观察办公室。
- 玩家从区域划分目录选择研发区、销售区、服务器区、会议区、招聘区等部门。
- 玩家以大像素区块为单位框定区域。
- 玩家在区域内摆放设施，例如办公桌、白板、服务器、会议桌、电话工位。
- 设施有升级梯度，等级越高价格越高，提供的效率、容量、稳定性或士气增益越高。
- 玩家通过员工管理入口招人、分配团队、查看员工能力、特长、正负特性、薪资和状态。

第一批区域方向：

- 产品室：研发产品、修复质量、探索 PMF。
- 销售区：寻找客户、推进大客户、提升 MRR。
- 服务器区：支撑稳定性、云成本和交付能力。
- 会议室：董事会、融资、战略和重大事件。
- 招聘区：招募员工、调整团队结构、管理士气。
- 市场区：品牌、媒体、活动和客户线索。

### 3.2 空间经营代替财务考试

复杂商业机制必须包装成简单取舍：

- 扩大研发区：产品产能更高，但占用面积和现金。
- 升级办公桌：员工效率更高，但固定支出上升。
- 增加销售工位：获客能力增强，但产品差时会放大流失。
- 扩服务器区：稳定性提升，但云成本和维护成本上升。
- 招聘员工：部门产能提升，但薪资压力增加。
- 缩减区域或出售设施：延长现金流可支撑时间，但增长放慢。

行动和设施默认只展示取舍，不展示公式；高级详情可以作为可选层。

### 3.3 规则角色反馈

近期不做 AI 玩法。角色反馈先由确定性规则和模板生成：

- CFO：现金流、预算、融资、破产预警。
- CTO：产品质量、技术债、研发路线。
- COO：交付、团队士气、组织压力。
- 投资人：估值、增长、风险偏好、谈判反馈。
- 客户：需求、抱怨、续费、流失原因。
- 竞品：价格战、产品升级、抢客户、融资消息。
- 媒体/市场：声誉、舆情、行业叙事。

这些反馈必须来自结算后的事实快照，不能凭空生成经营事实。

### 3.4 员工自主模拟

员工不是静态数值，也不是纯装饰角色。

- 员工有能力和特长，决定适合的职位和工种。
- 员工有随机正面和负面特性，例如高效、易疲劳、学习快、情绪化、爱迟到、擅长沟通等。
- 员工会随游戏时间推进产生需求：疲劳、休息、娱乐、上厕所、情绪波动、生病等。
- 员工状态会影响产出、士气、协作、离职风险和特殊事件。
- 员工培训和成长是辅助系统，不能盖过公司经营收益主线。

### 3.5 游戏时间推进

游戏不是纯回合按钮推进，而是时间缓慢流动的经营模拟。

- 支持暂停。
- 支持正常速度。
- 支持二倍速。
- 支持三倍速。
- 时间推进影响员工行为、设施产出、客户增长、成本消耗和月度结算。

### 3.6 可复盘故事

每局都要能回答：

- 为什么成功或失败？
- 关键转折点是什么？
- 哪个角色提醒过玩家？
- 当时有什么可选补救？
- 下局可以怎么改？

失败不是惩罚弹窗，而是一次可复盘的创业故事。

## 4. 核心循环

经营循环：

1. 游戏时间持续推进，玩家可以暂停、正常速度、二倍速、三倍速切换。
2. 观察公司目标、收益、现金流可支撑时间、客户和部门瓶颈。
3. 划分或调整部门区域。
4. 摆放、移动、出售或升级设施。
5. 招聘员工、分配工种、查看能力特长、处理员工需求。
6. C# Core / TurnEngine 根据空间、设施、员工状态和经营意图结算。
7. 月度战报展示收益、现金流、客户、目标进度、成就变化和下一回合压力。

中期循环：

1. 建立产品基础。
2. 找到可验证客户需求。
3. 在现金流压力下选择增长、融资或收缩。
4. 扩张团队和销售体系。
5. 形成产品、市场、资本、盈利或大客户路线。

长期循环：

1. 形成公司风格：产品信仰、资本狂飙、大客户、精益创业、产业合作等。
2. 渐进解锁 PMF、回款、毛利、组织、合规、上市路径。
3. 进入结局：破产、被迫出售、A 轮成功、行业独角兽、IPO、技术孤岛、创始人出局等。

## 5. 暂不做 AI 玩法

近期版本不做：

- AI 自由指令。
- AI 角色对话。
- AI 事件叙事。
- AI 复盘生成。
- AI Agent。
- API 或模型接入。

保留的边界：

- 角色反馈先由规则模板生成。
- 经营结算只由 C# Core / TurnEngine 决定。
- 后续如恢复 AI，也只能消费事实快照，不能修改核心数值。

推荐数据流：

```text
办公室布局 / 设施 / 员工
  -> 部门产能
  -> 经营意图
  -> StateGuard
  -> C# Core 确定性模拟
  -> 董事会 / 客户 / 竞品 / 洞察事实
  -> Godot 月度战报
```

## 6. 资产与美术管线

生成型视觉资源继续遵守：

- 使用 image-2。
- Prompt 存入 `design-assets/image-2/prompts/`。
- 可复用导出存入 `design-assets/image-2/exports/`。
- 资产登记进入 `design-assets/manifest.json`。
- Godot 引用稳定导出，不直接依赖生成过程。

优先级：

1. 办公室房间背景和热点区域。
2. 员工、董事会、客户、投资人头像。
3. 行动卡插画。
4. 事件、危机、成就图标。
5. 结局复盘插画。

重要 UI 文案不应烘焙进图片。

## 7. Godot 路线图

### G0：工程与规则桥接

目标：Godot 项目可启动、可编译、可调用 C# Core。

已完成：

- Godot 4.6.x .NET 工程骨架。
- 主场景和办公室热点脚本。
- `PreparedActionSnapshot` / `TurnResultSnapshot`。
- `GodotTurnBridge` 调用 `StartupSim.Core`。
- CI 中构建 Godot C# 项目。

### G1：办公室建造垂直切片

目标：不用 Web，Godot 中可以完成“框定区域 -> 摆放设施 -> 招聘员工 -> 执行月度结算 -> 显示月报”。

验收：

- 至少 3 类可框定区域。
- 区域以大像素区块为单位。
- 至少 3 类可摆放设施。
- 设施至少 2 个升级等级。
- 有员工管理入口。
- 可以招聘、查看能力、特长、正负特性、分配员工。
- 员工会随时间产生疲劳、休息、娱乐、厕所、情绪和生病等状态。
- 支持暂停、正常速度、二倍速、三倍速。
- 行动提交后通过 C# Core 结算。
- HUD 显示现金、现金流可支撑时间、MRR、用户、产品、声誉、股权、估值。
- 月度战报优先显示收益、现金流、客户、目标和成就变化。

### G2：C# Core 规则扩展

目标：Godot 可以离线跑完 12 个月基础局。

验收：

- StateGuard 可拦截不可承受预算。
- 融资估值、拒绝和反报价同源。
- 董事会、竞品、客户、洞察输出事实快照。
- 结局和复盘事实可由 Godot 展示。

### G3：办公室模拟感

目标：办公室看起来像经营空间。

验收：

- 房间有状态：正常、风险、机会、改善、阻塞。
- 员工有状态：工作、休息、娱乐、上厕所、情绪波动、生病。
- 角色或气泡反馈来自已结算事实。
- 行动结果有轻量动画或状态变化。
- 信息密度低于旧 Web 仪表盘。

### G4：反馈与复盘体验

目标：规则角色反馈、月报和复盘成为核心经营反馈。

验收：

- 角色反馈引用结算事实。
- 月报解释空间、设施和员工导致的结果，并优先呈现公司收益、现金流、客户、目标和成就变化。
- 复盘引用关键回合事实。
- 不依赖 AI 服务也能完整游玩。

### Beta：可分发桌面版

目标：Godot 导出 Windows 可试玩包。

验收：

- 本地存档。
- 离线 demo。
- 导出脚本。
- 资源体积和加载流程可控。
- 复盘、成就和至少 5 个结局可展示。

## 8. 当前不做

- 不再推进 Unity 主线。
- 不继续大规模打磨 React/PixiJS 作为最终外壳。
- 不做完整 3D 办公室。
- 不做多人联机。
- 不把上市、债务、回款、PMF 多指标一次性压给玩家。
- 不做 AI 自由指令、AI 对话或模型接入。

## 9. 下一步执行建议

下一步应做 `G1：Godot 本地可玩垂直切片`：

1. 给 Godot 补自动化脚本：检查、导入、构建。
2. 建立办公室网格和区域框选。
3. 建立区域目录：研发区、销售区、服务器区。
4. 建立设施目录和设施升级数据。
5. 建立员工管理入口、员工能力、员工特长、正负特性和需求状态数据。
6. 建立时间推进和速度控制。
7. 将空间布局、设施、员工能力和员工状态转成经营产能快照。
8. 提交后显示收益、现金流、客户、目标和成就变化。
9. 添加 Godot/C# 侧测试或脚本检查。
10. commit + push，并确认 CI 绿色。
