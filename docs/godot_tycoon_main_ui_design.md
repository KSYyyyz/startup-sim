# Godot 主界面 Tycoon 化设计规格

## 1. 目标

Startup Sim 的 Godot 主界面应从“右侧常驻看板 + 中间办公室格子”调整为“房间主导的办公室经营模拟界面”。参考方向是《疯狂游戏大亨 2》这类 tycoon 主界面：办公室和房间占据主要视野，状态、工具、事件和详情以 HUD、工具栏、浮动提示和弹窗承载。

本设计不复制参考游戏的素材、代码或具体玩法，只吸收其界面组织方式：玩家先看到公司空间，再通过底部工具栏和情境面板进行操作。

## 2. 参考结论

《疯狂游戏大亨 2》的有效界面特征：

- 主画面是可读的办公室/房间，而不是数据仪表盘。
- 房间边界、员工状态、任务进度和事件气泡直接叠在场景中。
- 顶部区域承载公司状态、通知和重要全局图标。
- 底部横向工具栏承载建造、员工、项目、市场、财务、报告、速度控制等入口。
- 详情信息以弹窗或小型情境面板出现，避免长期遮挡办公室。

## 3. Startup Sim 主界面结构

本轮将 `G2OperationsPanel` 从右侧常驻看板改成全屏 HUD 控制层，保留现有 C# 控制器和 C# Core 桥接。设计原则是：右侧常驻看板退场，办公室本体成为玩家的第一信息源。

场景结构：

- `TopStatusBar`：顶部薄状态栏，显示现金、现金流可支撑时间、MRR、用户、产品、月份和速度按钮。
- `FloatingEventFeed`：顶部偏中浮动事件条，显示当前操作反馈、月结提示和错误反馈。
- `BottomActionDock`：底部横向工具栏，放置区域、设施、员工、存档、读取和月结入口。
- `RoomContextPanel`：左下轻量情境面板，显示公司目标、产能预览和当前房间/格子操作语义。
- `MonthlyReportModal`：月结或读取复盘后才显示的报告弹窗，替代主屏常驻文字墙。

## 4. 行为规则

- 平时办公室画面优先，网格只作为低噪音辅助存在。
- 进入划区或摆设施模式时，才强化网格、预览和合法性反馈。
- 月结结果不常驻占屏，结算后打开 `MonthlyReportModal`。
- 玩家点击关闭后回到办公室主视野。
- 玩家可见文案继续使用“现金流可支撑时间”，不使用“跑道”或 `Runway`。
- Godot UI 只展示和组织交互，不复制经营规则；月结仍通过 C# Core。

## 5. 验收标准

- 主场景不再出现 `PanelBacking` 或“公司经营面板”这类右侧看板结构。
- 主场景包含 `TopStatusBar`、`BottomActionDock`、`FloatingEventFeed`、`RoomContextPanel`、`MonthlyReportModal`。
- 原有划区、摆设施、招聘、训练、速度、月结、存档、读取按钮仍能连接到现有控制器方法。
- 开局顶部状态栏显示 C# Core 初始指标。
- 自动或手动月结后，顶部状态栏更新，浮动事件条提示月结，月报弹窗显示报告。
- Godot C# build、内容检查、pytest 和 CI 通过。
