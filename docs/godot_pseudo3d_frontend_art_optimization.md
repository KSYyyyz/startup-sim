# Godot 伪 3D 轻像素前端美术优化方案

状态：美术生产与 Godot 接入约束
日期：2026-05-19
适用范围：`godot/StartupSimGodot` 主场景、HUD、数值反馈、美术资源 v1.1+

本文基于当前项目文档、`scenes/main.tscn`、`OfficeGridView.cs`、`G2OperationsPanelController.cs`
和现有 v0.1-v1.0 美术包重新整理。目标是把 Startup Sim 的视觉方向收束到：

> 类似经营建造游戏的斜俯视主场景，但保持 Startup Sim 自己的原创伪 3D 轻像素风格。

这里的“伪 3D”不是现在就切到完整 3D 或真等距地图，而是让 2D 资源具备统一视角、厚度、阴影和遮挡层次，
在 Godot 当前矩形网格原型上先获得接近《疯狂游戏大亨》一类办公室经营游戏的可读空间感。

## 1. 核心玩法对视觉的要求

Startup Sim 的主线是公司经营结果，不是摆家具本身。前端美术必须支持玩家快速读懂三件事：

1. 公司现在靠什么增长：产品、销售、服务器、招聘、会议、市场等部门要有清楚空间归属。
2. 当前瓶颈在哪里：设施状态、员工状态、现金压力、客户反馈、升级进度要能浮现在办公室里。
3. 下一个经营取舍是什么：右侧面板和月报用 Godot 文本解释数值原因，美术提供图标、状态、趋势和氛围。

因此办公室画面要像“可操作棋盘”，不是纯背景插画；HUD 要像“经营决策台”，不是全屏数据仪表盘。

## 2. 推荐视觉目标

### 2.1 风格定义

- 视角：斜俯视 2.5D，能看到家具顶部、前侧面和一点右侧面。
- 像素感：轻像素，不做低分辨率硬锯齿；边缘清晰，局部保留像素块状细节。
- 轮廓：中等深色描边，保证 32-96px 显示时仍能识别。
- 光照：统一从左上方入光，右下方投柔和透明阴影。
- 色彩：办公室主体温暖但克制，状态反馈用高饱和小面积点亮。
- 文本：不把中文、数字、月份、指标名烘焙进图片，全部由 Godot UI 渲染。

### 2.2 与“疯狂游戏大亨式视角”的关系

可以学习的是：办公室作为主游戏面、房间和设施承载经营含义、员工在空间里形成忙碌感。

不能复制的是：具体美术、UI、房间造型、图标、角色、品牌符号和专有布局。Startup Sim 应该走更轻、更清晰、更适合 2D Godot 原型的版本：

- 不做完整 3D 自由镜头。
- 不急着做真等距投影。
- 不把办公室做成满屏装饰。
- 先把透明设施、员工、状态 FX、HUD 视觉系统做扎实。

## 3. Godot 可实现性判断

### 3.1 当前最稳方案：矩形逻辑网格 + 伪 3D 资源

当前 `OfficeGridView` 是 12x8、64px 的矩形逻辑格，并通过 `_Draw()` 绘制地板、区域、设施、员工和状态图标。
这个结构可以继续用，短期只需要美术资源配合：

- 设施 sprite 可以比单格更高，底部锚点对齐格子底边，顶部向上延展。
- 2x1、1x2、2x2 设施用更大的透明 PNG，逻辑占格仍由 C# / Godot 数据决定。
- 员工 sprite 用脚底或身体底部作为排序锚点。
- 阴影独立画进透明资源或单独 shadow atlas。
- FX 图标仍用 v0.8 的透明素材，由 Godot 控制飘移、淡出和缩放。

这条路不要求重写点击命中、网格坐标或区域框选，适合现阶段。

### 3.2 中期可选方案：斜投影 OfficeGridView

当办公室扩大、遮挡排序变复杂、玩家希望画面更接近真等距时，再考虑把格子绘制改为斜投影：

```text
screen_x = origin_x + (x - y) * tile_w / 2
screen_y = origin_y + (x + y) * tile_h / 2
```

代价是必须同步改：

- 鼠标反算格子坐标。
- 区域框选预览。
- 设施占格绘制和排序。
- HUD 与办公室世界的相对布局。
- art atlas 的地板、墙、门窗、设施锚点。

所以它不应该挡住当前 G1/G2 可玩闭环。先用矩形逻辑网格配伪 3D 资源，等玩法稳定后再换投影。

### 3.3 不建议现在做的方案

- 真 3D 办公室：会过早引入建模、相机、碰撞、遮挡和灯光成本。
- 全屏静态办公室插画：接入快，但会削弱可建造玩法。
- 大量立绘和头像：短期对主循环帮助小，不能替代员工在办公室里的活动表现。

## 4. 页面布局优化

当前 `main.tscn` 的有效结构是：

- 左侧 `OfficeBackdrop` + `OfficeGridView`：办公室主棋盘。
- 右侧 `G2OperationsPanel`：区域、设施、员工、时间、月报和指标。
- Godot 文本标签展示现金、现金流可支撑时间、MRR、用户、产品等。

建议保持 1280x720 第一版布局，但调整视觉权重：

### 4.1 办公室主视区

- 左侧 70% 应是可操作办公室，不要被 UI 覆盖。
- 网格线默认弱化，只在划区、摆设施、悬停时增强。
- 区域颜色要像半透明地贴或地毯，不要像调试色块。
- 背景 v0.7.1 作为边界和氛围，未来 v1.1 用透明墙角、门窗、光影、线缆、地毯补空间层次。

### 4.2 顶部/右侧经营数值

主界面默认只放 5 个关键指标：

- 现金
- 现金流可支撑时间
- MRR
- 用户
- 产品

辅助指标如声誉、估值、股权、团队压力、服务器稳定性进入详情或月报，不要全部常驻主界面。

对应美术需要：

- KPI 小图标：现金、时间、收入、用户、产品。
- 小型趋势箭头：上涨、下跌、持平、警告。
- 面板底纹和分割线：轻像素、半透明、不会压过中文文本。

### 4.3 右侧操作面板

右侧面板应该像一个“经营控制台”：

- 区域按钮：研发、销售、服务器。
- 设施按钮：办公桌、白板、机柜，后续扩展会议桌、电话销售位、休息区。
- 员工按钮：招聘、训练、分配、查看状态。
- 时间按钮：暂停、1x、2x、3x、推进月份。
- 月报区域：结算后显示本月事实和下一月压力。

美术只提供按钮皮肤、图标、选中态、禁用态、面板框和徽章；按钮文字继续由 Godot 渲染。

## 5. 现阶段资源够不够用

### 5.1 已经够支撑的部分

当前资源已经足够支撑一个“能跑起来的办公室经营原型”：

- v0.7.1：公司主场景背景，能承载办公室氛围。
- v0.4 / v0.6：地板与区域 overlay，可以支撑划区可读性。
- v0.8：透明业务反馈 FX，适合 OfficeSignal、客户、现金、训练、升级等短反馈。
- v0.9：3 类设施的 8 种状态，足够让办公桌、白板、机柜有动态反馈。
- v1.0：4 类员工的 8 种活动状态，足够表达工作、休息、娱乐、生病、训练、压力等自主行为。

也就是说，资源已经够“接入一版动态表现”，不够“形成稳定的伪 3D 轻像素成品观感”。

### 5.2 当前明显不够的部分

为了达到目标视角和视觉品质，还缺：

- 统一伪 3D 地板、墙边、墙角、门、窗、柱、入口、窗光。
- 模块化办公室装饰：线缆、地毯、工位阴影、桌面小物、植物、打印机、饮水机。
- 大尺寸设施：2x1、1x2、2x2 的会议桌、电话销售位、服务器组、休息区、招聘台。
- 设施升级层级：当前有状态，但缺从低级到高级的外观差异。
- 员工 4 向小动画：当前 v1.0 是活动状态图，不是完整行走/工作动画序列。
- UI 视觉系统：按钮状态、面板底、KPI 图标、趋势箭头、月报卡片、目标徽章。
- 报告/复盘视觉：董事会、客户、竞品、风险、成就、失败原因对应的图标和卡片资产。

## 6. v1.1 之后资源顺序

### v1.1：伪 3D 办公室基础包

目的：让办公室看起来从“平面网格原型”升级为“有厚度的公司主场景”。

建议产物：

- 透明 overlay atlas：墙角、门、窗、入口、柱、玻璃隔断、线缆、地毯、阴影、窗光。
- 地板/墙面 tile atlas：浅色办公地砖、深色走廊边、可建造边界、不可建造边界。
- build marker：可放置、不可放置、选中、悬停、区域起点、区域终点。
- contact sheet preview 和 individual PNG。

Godot 接入方式：仍叠在 `OfficeGridView` 之上，不改变逻辑格。

### v1.2：伪 3D 大设施包

目的：让玩家一眼看出部门能力，而不只是在格子里看到小图标。

优先设施：

- 2x1 产品白板 / 研发桌组。
- 2x1 电话销售位。
- 1x2 服务器架组。
- 2x2 会议桌。
- 2x1 休息区。
- 1x1 咖啡机 / 打印机 / 植物 / 招聘台。

每个设施至少有：

- idle
- active
- upgrading
- blocked
- high_efficiency

### v1.3：员工 4 向活动动画包

目的：让办公室有“公司正在运行”的生命感。

优先角色：

- 研发
- 销售
- 运维
- 综合行政 / HR

每类角色先做：

- walk down/right/up/left
- working
- rest
- training
- pressure

角色必须继续拉开年龄、脸型、发型、服饰、饰品、表情和朝向，不能同脸同方向。

### v1.4：HUD 与数值展示包

目的：把经营数据从临时标签变成可读的游戏 UI。

建议产物：

- KPI icon atlas：现金、现金流可支撑时间、MRR、用户、产品、声誉、稳定性、团队压力。
- trend icon atlas：上升、下降、持平、警告、目标完成、风险加剧。
- UI chrome atlas：面板底、按钮 normal/hover/pressed/disabled、tab、badge、divider。
- 月报卡片底图：成功、警告、风险、机会、成就。

所有中文和数字仍由 Godot 文本渲染。

### v1.5：经营事件与复盘包

目的：增强月报、董事会、客户、竞品、洞察和失败复盘的可记忆性。

建议产物：

- 董事会反馈图标。
- 客户反馈图标。
- 竞品事件图标。
- 现金流危机图标。
- 产品突破图标。
- 团队压力图标。
- 成就徽章和失败结局徽章。

## 7. image-2 生产约束

从 v1.1 开始，所有正式美术相关产物都按 image-2 路线处理：

- 正式资源必须由 image-2 生成或基于 image-2 输出整理。
- Prompt 必须随资源包保存到 `prompts/`。
- 生成源图必须保存到 `sources/` 或 `raw/`。
- Godot 使用的导出图必须进入 `exports/`。
- 透明交互资产必须是 RGBA PNG，四角 alpha 为 0。
- atlas 必须提供 slice guide。
- individual PNG 必须与 atlas 语义一致。
- 体内路径是主资源，`D:\美术资源\startup-sim\...` 只是备份。

从 v1.1 开始，所有 atlas cell 和 individual PNG 还必须遵守
`docs/art_asset_metadata_standard.md`：每个贴图都要有稳定 `id`、中文说明、
推荐层级、锚点、逻辑占格、视觉尺寸、用途和 Godot 接入提示，避免接入侧靠视觉猜测。

允许本地脚本做的事情：

- 裁切、缩放、拼 atlas、切 individual PNG。
- 去除 image-2 输出中的背景色并生成 alpha。
- 生成 contact sheet preview。
- 校验 RGBA、alpha、尺寸和备份 hash。

不允许本地脚本替代的事情：

- 手绘正式图标。
- 用 SVG/几何图形假装正式美术。
- 用纯程序色块充当最终艺术资源。

## 8. 给 Godot 接入会话的关键提示

接入 v1.1-v1.4 时，不需要一次性重构。优先顺序是：

1. 在 `OfficeGridView` 增加视觉资源引用，不改变核心规则。
2. 让 facility visual 支持 `visual_state` 和多格 destination rect。
3. 让 employee visual 支持 `current_activity` 和 direction。
4. 让 FX 支持短时队列：生成、上浮、淡出、销毁。
5. 让 HUD 使用图标和面板皮肤，但文本仍用 Godot Label。
6. 当视觉层复杂到 `_Draw()` 难维护时，再拆 `FacilityLayer`、`EmployeeLayer`、`FeedbackFxLayer`。

不要让 Godot 表现层结算经营数值。现金、MRR、用户、产品、估值、股权、客户流失等仍来自 C# Core 结果。

## 9. 当前推荐结论

下一批不应该继续做大头像或纯展示插画，而应该做：

1. v1.1 伪 3D 办公室基础包。
2. v1.2 伪 3D 大设施包。
3. v1.4 HUD 与数值展示包。

v1.3 员工 4 向动画也重要，但最好排在办公室基础包之后，否则角色会漂浮在平面网格上，空间感仍然弱。

最小可玩视觉目标是：

> 玩家不看右侧面板，也能从办公室里看出公司有哪些部门、哪里在产出、哪里卡住、谁压力大、哪个经营信号刚发生。
